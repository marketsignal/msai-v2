## Minimal design

1. A standalone standard-library Python retention CLI consumes a small JSON config, defaults to report-only and emits structured JSON. Config explicitly names the Docker executable/context and expected daemon ID; mismatch, malformed metadata or failed inventory means no deletion. Use full inspected image IDs, not abbreviated IDs or global prune.
2. Configured ownership groups contain **exact repository allowlists**, never automatic prefix ownership. VM groups are the configured backend and frontend repositories. The local allowlist explicitly names the observed historical MSAI iteration repositories and stable MSAI build repositories approved at installation; one local group spans them. Newly seen MSAI-looking repositories are reported as unapproved and preserved until explicitly enrolled. Document using stable enrolled repositories for future builds. Default installer configs use zero arbitrary newest-version reserve. Keep all images referenced by **any** running/stopped container, explicit protected refs/IDs and VM current/last-good deployment refs. Local V2 baseline/qualified/control pins remain while qualification is active; VM defaults no longer pin older historical releases. Preserve unknown dangling images, unknown/mixed aliases, ambiguous group membership, missing Created metadata and multi-tag images. Current local inventory has only one multi-tag MSAI ID and it is a qualified-base pin, so preserving it does not prevent the observed backlog cleanup. Default creation-age grace is seven days; operator-selected alternative age is explicit and no age rule overrides pins. Existing installed/operator-added pins remain preserved on installer update; retiring one requires a deliberate reviewed config change.
3. Immediately before each deletion, refresh container references, aliases and deployment pins. Remove the explicit full ID with `docker image rm --no-prune`, never force; native reference conflicts fail safely and are reported. Never remove containers, networks, volumes, builder cache, registry objects or parent images. A separate disposable native fixture will prove actual deletion and preservation behavior.
4. Use a nonoverlap lock for local scheduled/manual retention, and skip/report if a build/deploy is observed; native full-ID conflict refusal is additional protection, not a claimed transaction against arbitrary concurrent clients. VM growth is confined to deployment pulls, so use the existing serialized deploy workflow's pre-pull hook rather than introducing a competing VM timer. Manual VM application requires a current quiet-deployment check. Snapshot current and last-good metadata persistently; read structured env assignments as data, never source/eval them. Resolve registry/image/SHA fields into exact refs and fail closed on invalid/missing expected pin authority. Preserve first-deploy sentinel semantics. Recover current from its persistent mirror when /run is absent; refresh the persistent current mirror on rollback. Restarts must not silently lose rollback protection.
5. A small local installer stages reviewed executable/config at a stable path independent of a task worktree and creates a per-user LaunchAgent. Pin absolute Python/Docker paths, Docker context and daemon identity. If Docker is unavailable, log an explicit skip without starting it or containers; report wrong-engine/config/cleanup failures. Scheduler installation is idempotent and verified through native launchd status. VM uses a stable installed helper plus the tracked pre-pull hook, not a periodic timer. Install or apply only after concrete reviewable operational approval; do not claim a source-only future hook is already active on the existing VM.
6. After bounded cleanup, report host filesystem available bytes and Docker disk usage. A configurable5GiB floor produces a visible nonzero disk-pressure result; future VM deployment refuses to pull another image below that floor after retention. On Mac label host-filesystem free space honestly: it does not prove free space inside Docker Desktop's disk image. Retention cannot guarantee against volumes, unrelated workloads or protected images filling disk; those are explicit reported limitations, not permission for broad deletion.
7. Run the VM guard/retention **before Phase4 rewrites current metadata**, with the prospective target passed as an explicit pin, so floor refusal cannot record an unpulled target as current/last-good. Preserve existing trap/FAIL behavior; a noncritical cleanup refusal may warn, but inadequate headroom refuses the pull without changing app or image authority. Stage new helper files only when present in the target payload so dispatching a pre-fix SHA still works. Current/last-good persistence also restores the mirror on rollback. Preserve user-added pins. Add the owning unittest-discover command to CI's explicit infra list. No claim that future pipeline adoption is active until separately published/deployed.
