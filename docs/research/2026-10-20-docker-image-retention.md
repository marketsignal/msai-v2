# Docker image accumulation: current vendor behavior

Checked October20,2026 through a fresh research-first agent; Context7 quota was unavailable, so research used official vendor documentation and Moby source. No infrastructure mutations were performed by research.

- [Docker prune behavior](https://docs.docker.com/engine/manage-resources/pruning/) distinguishes images, containers, volumes and build cache. Global system prune would delete stopped containers and is unsuitable here. Image prune has no repository filter; `-a` includes unused tagged rollback images.
- [Image prune filters](https://docs.docker.com/reference/cli/docker/image/prune/) use image creation time, not last use/pull. Count retention and rollback selection require inspected IDs. Repeated same-key label filters can combine broadly; do not use negative label filters as a purported ownership guarantee.
- [Image removal](https://docs.docker.com/reference/cli/docker/image/rm/) supports nonforced explicit IDs and `--no-prune`. All aliases must be inspected; native nonforced tag deletion can remove an alias while another alias remains, so protect whole IDs referenced by any container. Preserve multi-tag or ambiguously owned images rather than force deletion.
- [BuildKit GC](https://docs.docker.com/build/cache/garbage-collection/) limits build cache rather than retained deployment images. Shared local builders cannot safely be cleaned on another project's behalf.
- [Docker space accounting](https://docs.docker.com/reference/cli/docker/system/df/) includes shared layers. Actual filesystem before/after measurements are authoritative; logical image-size sums are not promised reclaimable bytes.
- [Docker Desktop Mac disk behavior](https://docs.docker.com/desktop/troubleshoot-and-support/faqs/macfaqs/) distinguishes allocated host bytes from maximum sparse-image capacity. Shrinking the disk-image limit deletes its content, so it is excluded. Docker Desktop internal free space is not established by macOS host filesystem free space alone.
- [systemd calendar timers](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html) with Persistent catch missed calendar runs; one-shot services should not remain active after completion.
- [Apple launchd scheduling](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html) supports per-user LaunchAgents with absolute program paths, calendar scheduling and logs. Agents require the user logged in; sleep/power-off behavior is not a guarantee of uninterrupted maintenance.

Incident-specific evidence remains local. The VM root reached61GB/100% with inodes11%; Docker showed134images and7container-referenced IDs. An explicitly approved eleven-image cleanup recovered1,130,737,664bytes. Current source has no owned-image retention. Local MSAI tags span multiple research iteration repositories. Last-good VM image metadata resides only in volatile `/run`; current metadata has a persistent mirror. Retention must preserve both exact current/rollback refs and all container IDs, and coordinate with deployment image selection/pull.
