# Nautilus native capabilities and upgrade assessment

**Assessed October 5, 2026. MSAI source: `84707a47313766ef3fbe5c251f8488b9dc2cb822`.** This assessment combines two focused code investigations, official upstream sources, installed-package inspection and isolated Python probes. Documentation edits are not application repairs. No running service, project dependency, production data or broker connection was changed.

**Follow-up:** the [executable runtime trial](2026-10-05-nautilus-runtime-trial.md) is now complete for its bounded scope and supersedes the recommendation to start a trial. It recommends direct V2 development, with compatibility still partial and production promotion unapproved. The table below preserves the earlier source/import evidence; its statements about unexecuted tests apply to that initial assessment only.

## Initial recommendation

Make **a bounded V2 compatibility trial the next batch**, before expanding engine-related data, cost, accounting or live code. V2 is the preferred direction to evaluate because that is where upstream development is moving. It is not yet an approved MSAI runtime. Use one native research path and one offline live integration path to establish the actual migration cost and gaps; do not create a general V1/V2 compatibility framework.

If those paths work, implement the minimum V2 migration and prove the affected application journeys before deployment. If a required capability fails, record its reproduction and owner, then consider 1.231.0 as a temporary bridge with its own checks. Do not automatically perform two upgrades. Keep 1.223.0 as the unchanged reference while evaluating candidates. Urgent independent security/correctness work need not wait for an engine migration.

## V2 opportunity and compatibility risks

Upstream RC3 added Python live-node Redis message-bus and cache backing plus hosted asynchronous lifecycle support. Therefore, the August transition's missing-feature list is not a valid current rejection of V2. RC3 also added normalized backtest result projections/digests; inspect their Python availability and meaning before using them as MSAI evidence. [RC3 release](https://github.com/nautechsystems/nautilus_trader/releases/tag/v2.0.0rc3).

RC6 adds same-venue execution routing and account lookup improvements, catalog migration tooling, per-instrument fee overrides and reconciliation diagnostics. These are relevant reasons to evaluate it. They do not prove compatibility with MSAI's account registry, data layout or projections. No speedup or maintenance saving has been measured. [RC6 release](https://github.com/nautechsystems/nautilus_trader/releases/tag/v2.0.0rc6).

The [release-pinned migration guide](https://github.com/nautechsystems/nautilus_trader/blob/v2.0.0rc6/MIGRATION_V2.md) describes V2 as the primary path; V1 receives limited critical-security backports after cutover. It changes strategy configuration, node lifecycle/registration, reports, catalog APIs and persistence setup. **Follow-up correction:** its statement that custom Python adapters are unavailable is stale relative to the release source and wheel; supported adapters still have cache/hosted-lifecycle constraints. Serialized snapshot publishing also has limits. [Exact documentation/source reconciliation](2026-10-05-nautilus-upstream-trial-addendum.md#one-pinned-migration-limitation-is-demonstrably-stale). Native PostgreSQL cache migrations concern that engine backend, not automatically MSAI's application database. Set economic assumptions explicitly: omitted margin leverage changes to 10x. Verify catalog/state compatibility on copies; image rollback alone cannot reverse changed data.

Prioritize these MSAI-specific migration contracts:

1. **Research:** strategy discovery/config constructors, inclusive execution bounds, instrument definitions, native fill/account reports and persisted financial meaning. Preserve the December 3 reference and independent tiny equity/futures fixtures; reconcile any expected engine behavior changes rather than blindly requiring every old result.
2. **Live lifecycle:** current code depends on `build`, `run_async`, disposal ordering and `node.kernel.trader` readiness. Exercise real native lifecycle transitions before porting historical workarounds. [Subprocess](../../backend/src/msai/services/nautilus/trading_node_subprocess.py):1358, 1392, 1760; [startup health](../../backend/src/msai/services/nautilus/startup_health.py):108.
3. **Events/state:** MessagePack stream decoding, topic/field names and direct V1 `CacheDatabaseAdapter`/`MsgSpecSerializer` cold reads are coupled to the old runtime. Feed actual engine events through the existing read models; prove deduplication, attribution and reconnect recovery. [Projection consumer](../../backend/src/msai/services/nautilus/projection/consumer.py):219; [position reader](../../backend/src/msai/services/nautilus/projection/position_reader.py):221.
4. **Cross-provider routing and safety wrappers:** prove Databento bars reach the intended strategy and orders resolve to the right IB contract/account. Reassess the symbology actor, failure-isolation mixin and halt wrapper against supported native extension points; do not delete them solely because routing exists. [Symbology actor](../../backend/src/msai/services/symbology_shim_actor.py); [failure isolation](../../backend/src/msai/services/nautilus/failure_isolated_strategy.py).

## Decision boundary and remaining proof

**Initial assessment complete; at that point migration compatibility remained unproven.** Those probes established packaging and selected API differences, not end-to-end trading correctness. Neither 1.231 nor RC6 had been run through MSAI, its Linux images, its real browser, a saved catalog/cache migration, or IB in that initial assessment. The [later trial](2026-10-05-nautilus-runtime-trial.md) adds native execution, isolated persistence and full dependency/image evidence without claiming application/browser/broker acceptance. Existing green tests that substitute fake nodes cannot supply missing native or integration proof.

The [Master Plan](../../MASTER_PLAN.md#completed-batch-nautilus-native-reuse-and-version-decision) records the trial decision and subsequent acceptance. V2 is a development target; required application contracts and a credible state/rollback plan still gate adoption. Name any gap and compare the cost of a bridge versus waiting if that path becomes necessary. Preserve the remaining M01–M29 findings until their own evidence closes them.
