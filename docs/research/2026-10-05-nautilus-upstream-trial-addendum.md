No application files, dependencies, services, vendor accounts, catalogs or running Redis state were changed by this research. ## Most material trial contracts

### Python live lifecycle and Redis cache cannot be assessed independently

RC6 supplies Python Redis cache/message-bus builders; the old broad claim that Python V2 lacks Redis backing is obsolete. However, a **cache-database-backed node cannot run through `run_async()`**. Native-only nodes can use blocking `run()`. This restriction concerns cache database backing, not Redis external-message-bus backing. The [live configuration guide](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/docs/how_to/configure_live_trading.md#cache-database-configuration) and [binding source, lines 982–1025](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/crates/live/src/python/node.rs#L982) agree: the cache workers make blocking calls incompatible with the host event loop.

Redis supports strategy/actor load/save and cache snapshots. PostgreSQL cache backing does not provide strategy/actor state persistence. Strategy state is saved at most once per run, and disposal is required to close backing and flush buffered writes; a crash can lose changes since the last save. These are documented contracts, not a measured MSAI recovery result. The focused check is the **combined** lifecycle + Redis cache + actor/strategy-state configuration, including disposal and a second run, rather than separate successful constructors. Source: live configuration guide above.

Hosted Python runs borrow the node; capture cache, portfolio and stop handle before starting. Disposal during the run is a no-op. Concurrent nodes in a single process are unsupported, and a replacement live node on the same thread requires releasing references to the previous node. Python strategy callbacks remain synchronous on the processing thread. These restrictions directly inform the subprocess and failure-wrapper checks. [RC6 Python runtime contract](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/docs/concepts/python.md#ownership-and-lifecycle).

### One pinned migration limitation is demonstrably stale

The RC6 migration guide still says out-of-tree Python live adapters are planned/unsupported. The same release's [Python adapter guide](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/docs/developer_guide/python_adapters.md) describes a restored interface. Exact release source defines [DataClient/MarketDataClient/ExecutionClient and their factories](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/python/nautilus_trader/live/clients.py); the [builder detects custom factory subclasses](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/crates/live/src/python/node.rs#L2341) and registers them.

Therefore, an absolute missing-custom-adapter rejection is unsupported by RC6 source. The earlier source-only phase of this research did not execute custom factory registration from the released wheel; the subsequent [runtime trial](2026-10-05-nautilus-runtime-trial.md#live-lifecycle-persistence-and-projections) executed a custom Python data-client factory and confirmed the hosted/cache restriction. The adapter guide specifies an important remaining limit: custom Python clients cannot use Redis/PostgreSQL **cache** backing in either launch mode, because both run modes drive asyncio. They also use read-only cache views and queued typed outputs, so unchanged V1 adapters are not source-compatible. This contradiction is a reason to test the precise wheel contract, not to assume every item in a deferred-feature list remains current.

### Native Redis events are not an application replay guarantee

The [RC6 message-bus contract](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/docs/concepts/message_bus.md#external-egress-and-ingress) specifies Redis 6.2 minimum and wire fields `topic`, `type`, `encoding`, `payload`, plus `payload_kind=typed` for relevant control/execution/reconciliation messages. Missing `type` causes ingress to skip a record; omitted encoding defaults to JSON. JSON/MessagePack external egress includes account state, portfolio snapshots, order events and position events. These are distinct from full serialized order/position snapshots, whose external publication remains listed as deferred.

Bounded egress may drop messages when full, and the [live guide](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/docs/how_to/configure_live_trading.md#messagebus-configuration) says external ingress does not replay entries predating startup. Neither statement establishes the behavior of MSAI's separate consumer groups, PEL recovery, deduplication or cold readers. The trial must feed real emitted records into those readers and inspect their exact fields, type discriminator, decimal representation and restart behavior.

### Native portfolio analytics now expose account equity, with return fallbacks

RC6 exposes `Portfolio.equity()`, recorded snapshots and statistics. Default equity-curve capture occurs at account registration, UTC midnight and shutdown. Native margin equity adds unrealized PnL to balances; cash accounts with a base currency add open-position mark value. Portfolio returns need complete snapshots spanning at least two UTC dates. Same-day snapshots alone do not produce them; statistics can fall back to position returns. Unresolved common currency across accounts also causes fallback. Native analysis aggregates cached accounts after common-currency resolution. [Pinned portfolio contract](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/docs/concepts/portfolio.md).

Thus the December 3 one-day reference must reconcile account equity/cash flows and inspect the selected return series. **Executable follow-up:** RC6 actually recorded opening and closing snapshots on the same December 3 UTC date and returned 0.28%, matching account equity. The two-date wording above is an upstream documentation statement, not a universal rule established by the released wheel. [Trial results and limits](2026-10-05-nautilus-runtime-trial.md#research-behavior-actually-executed). A rendered native tearsheet or imported analyzer is insufficient. Shared-cash proof also needs simultaneous strategies whose combined demand exceeds a common funding limit, with order/position/account evidence. Separate weighted returns cannot establish that mechanism.

## Strategy behavior, adapter identity and state migration

RC6 changes indicator semantics: EMA/Wilder/DEMA/MACD use mean-seeded warmup; SMA/WMA remain zero before complete windows; RSI uses Wilder smoothing and a 0–100 scale. Fee models are mandatory for backtest venues, including zero fees. Instrument maker/taker fee fields are removed. Shared-venue account lookup becomes ambiguous and returns `None` without explicit identity. Live startup rejects unrecovered in-scope nonzero positions, and shutdown rejects unresolved retained submissions. These changes require expected-behavior fixtures; output drift cannot automatically be attributed to a broken port. [RC6 release notes](https://github.com/nautechsystems/nautilus_trader/releases/tag/v2.0.0rc6).

The [migration guide](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/MIGRATION_V2.md) changes Python config construction, explicit component registration, callbacks and order modification/cancellation arguments. Backtest nodes retain private engines; reports and cache/portfolio inspection use run-config IDs and require `dispose_on_completion=False`. Omitted leverage becomes 10x for margin and 1x for cash; mark-price preference defaults true. Old order-book pickle data is incompatible, and older catalog order-event schemas need migration/regeneration. Order average price/slippage are Decimal values and string dictionary fields. Keep cost/leverage/valuation assumptions explicit and compare state/catalog copies.

IB remains an official Rust/Python adapter without an extra. Its [pinned guide](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/docs/integrations/interactive_brokers.md) requires distinct process client IDs; execution client IDs cannot be multiples of 1000 because order-ID partitions use that modulus. Execution config retains explicit account identity; provider RAW symbology preserves security type, e.g. `AAPL=STK.SMART`. These documented identities do not prove MSAI routes a Databento-fed order to the intended broker contract/account.

The [pinned Databento guide](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/docs/integrations/databento.md) requires publisher metadata and documents the `EQUS` venue for `EQUS.MINI`. Overriding a venue such as XNAS to that dataset requires consistent downstream IDs: decoding without an explicit instrument ID emits `*.EQUS`. GLBX may use exchange MICs when configured. Bars default to close timestamps; vendor OHLCV timestamps begin at interval open. Exact publisher metadata, timestamp convention and symbol mapping belong in the fixture. No entitlement, historical-download completeness or live provider session was checked.

## Lifecycle and unresolved adoption risks

The migration guide gives V1 only critical-security backports for approximately three months after V2 cutover, with no new feature/parity work. It does not establish an exact calendar cutoff or promise a particular future patch. A V1 bridge is not a long-term support guarantee. Combined with upstream's explicit RC production caution, this leaves a real timing tradeoff; the research does not choose it.

Remaining evidence belongs to the trial: full Python 3.12 Linux backend resolution/imports; strategy constructor and discovery behavior; economic differences under explicit assumptions; source-to-wheel agreement for the disputed Python adapter interface; native cache lifecycle and recovery; real event ingestion and cold reads; shared funding; and data-to-IB identity. Offline fixtures cannot establish actual broker reconciliation, account identity, entitlement or capital safety. Application defects already recorded in the Master Map remain outside what upstream release availability can prove.

## Follow-up: complete application lock resolution

The October 5 follow-up compared the original `backend/uv.lock` with the main agent's isolated resolved locks under `.forge/local/evidence/nautilus-trial-2026-10-05/packaging/{v1,v2}/backend/uv.lock`. This is lock/metadata evidence, not an install or broker test.

**The V1 candidate's IB Async downgrade is explained by timezone-package constraints.** [IB Async 2.1.0 metadata](https://pypi.org/pypi/ib_async/2.1.0/json) requires `tzdata>=2025.2,<2026.0`, whereas [Nautilus 1.231.0 metadata](https://pypi.org/pypi/nautilus-trader/1.231.0/json) requires `tzdata>=2026.3`. No version satisfies both. MSAI allows `ib_async>=1.0.0`; [2.0.1 metadata](https://pypi.org/pypi/ib_async/2.0.1/json) has no `tzdata` dependency, permitting the observed resolution to IB Async 2.0.1 plus `tzdata==2026.5`. This is not an IBAPI-version conflict. V2 retains IB Async 2.1.0 and `tzdata==2025.3`.

This downgrade affects a directly used library: [account snapshots](../../backend/src/msai/services/ib_account_snapshot.py) construct `IB` and call `connectAsync`, `managedAccounts`, `accountSummaryAsync` and `portfolio`. No runtime regression in those calls was established by this read-only check; a successful dependency solve does not establish their broker compatibility.

**Msgspec is a concrete undeclared application dependency.** AST inspection found direct production imports in [backtest validation](../../backend/src/msai/api/backtests.py) line 154, [schema hooks](../../backend/src/msai/services/nautilus/schema_hooks.py) line 45, [projection consumer](../../backend/src/msai/services/nautilus/projection/consumer.py) line 47 and [cold position reader](../../backend/src/msai/services/nautilus/projection/position_reader.py) line 61, plus owning tests. It is absent from both the MSAI manifest and the resolved RC6 lock. Those unchanged paths cannot import it in a clean environment containing only that resolution. Explicitly supplying Msgspec would address package availability; it would not restore V1 Nautilus serializer/config APIs.

The same AST scan across `backend/src`, `strategies` and `backend/tests` found no direct imports of Fsspec, Portion, DefusedXML or `ibapi`; a text search also found no Fsspec references there. This bounded negative finding does not cover arbitrary dynamically imported user strategies or optional third-party functionality. No dependency or source edits were made by this follow-up.

## User-supplied Copilot comparison: checked additions and corrections

The user supplied a comparison researched against the upstream default branch. Its architectural/configuration/callback guidance broadly agrees with this investigation. Material additions were checked against RC6 commit `7b766f8825b2539c5b2ac1375e9d97b41c509edb`; copied guidance is not itself compatibility proof.

- **Custom Python factories:** the blanket unsupported claim is stale. The trial executed a real custom Python data client. Its hosted/cache restriction remains, so the comparison's brief `run()`/`run_async()` choice is incomplete for MSAI's persistence requirements.
- **Cancellation scope:** `cancel_all_orders` defaults to `strategy_only=True`. Setting false broadens the selected execution client's cancellation; it does not broadcast across clients. MSAI's example EMA strategy uses the default. Add distinct sibling-strategy preservation and intended account-wide cancellation tests. [Exact Python signature](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/crates/trading/src/python/strategy.rs#L2148), [implementation](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/crates/trading/src/strategy/mod.rs#L913).
- **Indicator acceptance:** compare callback counts, indicator values, signal/first-trade timestamps and order/fill timelines. ROC changes both percentage units and its lookback to `period + 1`; selecting fractional units alone does not restore V1 behavior. Bollinger bar input changes from typical price to close. No direct ROC/Bollinger usage was found in current MSAI source/strategies, so this is a rule for relevant strategy ports, not a new implementation task. [RC6 ROC](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/crates/indicators/src/momentum/roc.rs#L154), [V1 ROC](https://github.com/nautechsystems/nautilus_trader/blob/27a8e54e7ac3c57d6cbf8891f0283dfbaee97317/nautilus_trader/indicators/momentum.pyx#L170), [RC6 Bollinger](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/crates/indicators/src/momentum/bb.rs#L93).
- **Performance:** the [pinned upstream benchmark script](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/scripts/benchmark-backtest-versions.py#L1515) compares 1.231/Cython and RC6/PyO3 with matched interpreter/precision and multiple sessions. It was not run here. Rust architecture and smaller wheels do not establish a measured MSAI speedup.
- **Custom data/DataFrames:** the guide's blanket limitation needs qualification. RC6 source exposes a [Custom NautilusDataType](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/crates/model/src/python/data/mod.rs#L135), [node catalog querying](https://github.com/nautechsystems/nautilus_trader/blob/7b766f8825b2539c5b2ac1375e9d97b41c509edb/crates/backtest/src/node.rs#L610) and custom-data decoding. This source inspection did not demonstrate a Python custom-data node journey or restored V1 DataFrame inputs. Evaluate only when a required MSAI path needs them.
